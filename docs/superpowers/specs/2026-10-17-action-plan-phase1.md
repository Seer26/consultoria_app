# Fase 1 — Monitoramento do plano de ação

Escopo: planos e tarefas operacionais, evidências de comentário/link, histórico imutável, indicadores por plano e funcionário. Sem habilidades, avaliação de desempenho, uploads, integrações ou IA avaliativa.

Frontend selecionado: React em saas/apps/web, conforme saas/README.md. O Flutter continua sendo um app distinto com autenticação, mas ActionPlanPage não é referenciada pelo roteador nem pelos dashboards; seu controller usa _seed e /tasks é ModulePage. Não há fluxo ativo de monitoramento a duplicar nesta fase.

Arquitetura: ampliar o módulo action-plan existente (repository/service/controller/router) e adicionar migração 011 idempotente com registro em schema_migrations. Preservar tarefas antigas, agrupadas por empresa e diagnóstico em planos migrados. Português no contrato de status/prioridade; entradas antigas normalizadas apenas na migração. SQLite com foreign_keys, checks e chaves compostas para tenant.

Planos: título, descrição, companyId, submissionId opcional, status RASCUNHO/ATIVO/CONCLUIDO/CANCELADO, startDate, dueDate, progresso calculado, createdBy, timestamps. Tarefas: campos atuais e planId, startDate, progress, notes; status PENDENTE/EM_ANDAMENTO/AGUARDANDO_VALIDACAO/CONCLUIDA/CANCELADA e prioridade BAIXA/MEDIA/ALTA/CRITICA. ATRASADA é calculada, nunca persistida como status. Progresso geral é a média das tarefas não canceladas (zero para plano sem tarefas válidas). Conclusão de plano exige pelo menos uma tarefa válida e todas concluídas. Reabrir tarefa de plano concluído reativa o plano; tarefa cancelada/concluída é bloqueada para funcionário. Conclusão força progresso 100; reabertura redefine progresso 0, salvo valor explícito abaixo de 100. Datas sem horário usam início/fim do dia UTC.

Segurança: identidade/role/company são relidos do banco; não confiar em claims antigos nem em userId/createdBy do body. OWNER e ADMIN vinculados a tenant ficam restritos a ele. ADMIN global sem companyId escolhe explicitamente um tenant ativo. EMPLOYEE só lê planos com tarefas suas e somente suas tarefas/evidências/histórico, e pode alterar progresso/observações, iniciar e enviar para validação em plano ATIVO. Apenas gestão altera atribuição/prazo/prioridade e conclui/reabre. Atribuição requer usuário ativo da mesma empresa. Ocultar IDs de outro tenant com 404. Histórico e evidências sempre herdam empresa/tarefa validadas no servidor. Cadastro de contas fica restrito a ADMIN global autenticado para impedir escalada pelo endpoint público existente.

React: login real, seleção de empresa para ADMIN global, planos, dashboard, filtros, visão por funcionário, criação/edição de plano/tarefa, painel de detalhe com ações, evidências e histórico. API via proxy /api no Vite. Token apenas em memória/sessionStorage, mensagens de erro, estados vazios e carregamento; UI sem mocks no novo módulo. Evitar modais: formulários e detalhe no fluxo da página, cards em mobile.

Validação: testes HTTP contra app real e SQLite temporário, migração limpa/legada/repetida, workflows, validação de entradas, histórico transacional e isolamento explícito tenant B -> A em leituras e escritas. Teste de navegador com API real nas larguras 1440/1024/768/390. Lint, typecheck e build no runtime externo porque node_modules/dist são versionados no checkout. Nenhum commit, push, PR ou deploy.
